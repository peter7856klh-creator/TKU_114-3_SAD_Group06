# Candidate Requirements

| 需求編號 | 需求描述 | 類型 | 來源編號 | 本期是否納入 | 理由 |
| -------- | -------- | ---- | -------- | ------------ | ---- |
| FR-01 | 系統應提供發起揪團表單，讓團主可輸入出發地、目的地、時間、上限人數與預估總車資 | 功能性需求（FR） | INT-01 | 是 | 對應核心發起流程 |
| FR-02 | 系統應在首頁看板顯示可加入的揪團資訊，方便使用者瀏覽 | 功能性需求（FR） | OBS-01 | 是 | 對應看板瀏覽需求 |
| FR-03 | 系統應在使用者加入揪團後，重新計算每人應分攤的金額 | 功能性需求（FR） | INT-02 | 是 | 對應分攤計算核心任務 |
| NFR-01 | 系統應在介面上清楚顯示目前加入人數與剩餘名額 | 非功能性需求（NFR） | INT-03 | 是 | 提升使用者理解與操作信心 |
| NFR-02 | 系統應避免使用者在人數已滿額時仍然能再次加入 | 非功能性需求（NFR） | INT-04 | 是 | 保障流程正確與防呆性 |
| CON-01 | 本期原型不串接 Google Maps、即時聊天室、簡訊通知與金流 | 限制條件（constraint） | DOC-01 / AI-01 | 是 | 因為專案範圍與時程限制 |
