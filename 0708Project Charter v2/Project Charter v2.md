## C. 專案章程第 2 版（Project Charter v2）

### 1. 專案題目（Project Title）

校園揪團與共乘／分攤平台

### 2. 目標使用者（Target Users）

| 角色 | 需求特徵 |
| --- | --- |
| 團主（發起人） | 想快速發布共乘揪團，填寫出發地、目的地、時間與預估總車資，並掌握加入人數 |
| 團員（加入者） | 想快速找到符合自己時間與目的地的共乘行程，並知道自己應分攤的金額 |
| 一般使用者（潛在用戶） | 想在校園看板上瀏覽共乘資訊，並在有需求時加入揪團 |

### 3. 問題陳述（Problem Statement）

有通勤、外宿或特定採買需求的大學生，常常需要搭計程車或與他人共乘，但傳統社群發文揪人容易被洗版，難以即時掌握實際成團人數，也很難在成團後快速計算每個人要分攤多少錢。這些問題會造成找同伴的時間成本增加，也讓共乘流程變得不透明且容易出錯。

### 4. 專案目標（Project Goal）

在 5 週暑修時程內，做出一套簡單實用的校園共乘看板網站，讓學生能快速發起揪團、加入他人行程、查看共乘資訊，並透過內建的車資分攤計算功能，降低人工算帳與資訊不透明的問題。

### 5. 利害關係人摘要（Stakeholder Summary）

本專案的主要利害關係人包含團主、團員、一般使用者、課外活動組／生輔組、計程車司機與專案開發小組。團主與團員最直接受益於系統的便利性，學校行政與司機則關心共乘安全與秩序，而開發小組則必須在有限時間內完成可展示的原型。

### 6. 範圍內項目（In-Scope）

1. 基本註冊與登入
2. 填寫個人聯絡方式（如 LINE ID）
3. 發布揪團貼文，包含出發地、目的地、時間、人數上限與預估總車資
4. 首頁看板瀏覽與目的地簡單篩選
5. 一鍵加入揪團與動態分攤車資計算
6. 滿額時的防呆與狀態更新

### 7. 範圍外項目（Out-of-Scope）

1. Google Maps 實時定位與地圖導航 API 串接
2. 內建即時聊天室與會員評價／檢舉機制
3. 系統自動發送手機簡訊與 Email 滿額通知
4. 線上金流支付
5. 司機認證與複雜安全權限管理

### 8. 原型核心任務（Core Tasks for Prototype）

| 任務 | 主要角色 | 任務起點 | 任務流程 | 任務終點 | 初步驗收標準 |
| --- | --- | --- | --- | --- | --- |
| 發起共乘揪團並同步看板 | 團主 | 團主點擊「發起揪團」 | 填寫出發地、目的地、時間、上限人數與預估總車資，提交表單 | 系統成功寫入資料並回到首頁看板 | 看板即時顯示新揪團，資料正確且可被瀏覽 |
| 一鍵加入與動態分攤計算 | 團員 | 團員瀏覽首頁看板 | 點選符合需求的揪團並確認加入 | 系統更新成員名單並重新計算每人應分攤金額 | 加入後可看到最新分攤金額與成員狀態 |
| 滿額鎖定與聯絡資訊釋出 | 團主／最後一位團員 | 最後一位空位加入 | 系統判斷達到人數上限並更新狀態 | 系統變更為「已滿額」，並釋出成團後聯絡資訊 | 加入按鈕被封鎖，狀態顯示為已滿額 |

### 9. 初步成功標準（Initial Success Criteria）

1. 介面乾淨好操作，使用者不用看說明書也能在短時間內理解主要功能
2. 當團數量達到上限時，系統會立即阻止再次加入，避免超額
3. 車資拆帳計算結果正確，不會出現亂碼或錯誤的小數點
4. 使用者可以在首頁看板上順利發起與加入揪團
5. 原型展示時能完整呈現發起、加入與分攤計算的核心流程

### 10. 主要風險與應對方式（Major Risks and Responses）

| 風險 | 影響 | 應對方式 |
| --- | --- | --- |
| 範圍過大，包含過多第三方 API | 可能導致系統無法在 5 週內完成 | 將地圖、聊天室、簡訊通知與金流移至範圍外 |
| 需求資料不足，導致計算公式與欄位設計不符真實使用情境 | 可能造成功能不夠實用 | 透過訪談與同儕測試確認最重要的需求再實作 |
| Git 管理與版本整合混亂 | 可能導致最後整合時發生衝突或檔案遺失 | 使用 GitHub 進行定期 commit 與 push，維持主分支整潔 |
| 技術熟練度不足，前後端串接卡關 | 可能拖慢原型開發進度 | 優先實作最小可用功能，避免設計過於複雜 |
| 使用者亂填車資或不符合常理的資料 | 可能讓分攤功能失去意義 | 設定基本前端防呆與輸入限制 |

## D. 三分鐘短講提案稿

我們小組的題目是「校園揪團與共乘／分攤平台」。

有通勤、外宿或特定採買需求的大學生，常常需要搭計程車或與他人共乘，但傳統社群發文揪人很容易被洗版，難以即時掌握成團人數，也很難在成團後快速計算每個人要分攤多少錢。

本系統希望改善這個流程，讓學生能快速在看板上發起或加入共乘行程，並透過內建的車資分攤計算功能讓每個人清楚知道自己該付多少。我們的本期範圍包含註冊、發起揪團、首頁看板、加入揪團、分攤計算與滿額防呆；範圍外則包含地圖導航、即時聊天室、簡訊通知與線上支付。

期末原型會展示三個任務：第一，團主發起共乘揪團並同步看板；第二，團員一鍵加入並看到動態分攤金額；第三，當人數達到上限時系統會自動鎖定並顯示已滿額。

目前最大的風險是功能範圍可能過大，因此我們會先專注於最核心的三個任務，並把高風險功能放到範圍外，讓原型能在期限內順利完成展示。
