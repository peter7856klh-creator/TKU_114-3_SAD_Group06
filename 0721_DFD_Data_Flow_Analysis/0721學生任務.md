# 0721 學生任務

## 學生任務

### 任務 0：確認分析基準

開始畫圖前記錄：

1. 本次使用的需求文件版本：0714 需求文件包、updated_code_agent_brief.md、functional_requirements.md、acceptance_criteria.md、business_rules_data_constraints.md。
2. 目標流程與流程資料交換表版本：以 0720 工作紙中的 T-01 至 T-08 與流程資料交換表為基準。
3. 本期範圍內的核心使用案例：UC-01 建立揪團、UC-02 瀏覽看板、UC-03 檢視揪團資訊、UC-04 加入揪團、UC-05 檢視分攤金額、UC-06 檢視剩餘名額與滿額狀態。
4. 實作品版本或提交紀錄：目前第一個可操作切片，使用前端假資料與前端儲存方式實作。
5. 尚未確認的需求與規則：候補名單、地點選單與分攤小數顯示格式。

**輸出：**分析基準表。

**完成標準：**所有圖、表與實作品稽核使用相同版本；待確認內容沒有被當成正式規則。

### 任務 1：辨識外部實體與至少 8 筆資料交換

從流程資料交換表、使用案例與需求中找出：

1. 至少 3 個外部實體：團主、團員、一般使用者。
2. 每個外部實體送入系統的資料：發起揪團表單資料、看板查詢條件、加入請求。
3. 每個外部實體從系統收到的資料：新揪團建立結果、揪團卡片資訊、分攤計算結果、滿額狀態。
4. 每筆資料交換的需求與來源編號：FR-01 至 FR-07、AC-01-01 至 AC-05-01。
5. 至少 8 筆不同方向或不同內容的資料交換：EX-01 至 EX-08。

**輸出：**外部實體與資料交換清單。

**完成標準：**

1. 至少 3 個外部實體。
2. 至少 8 筆資料交換。
3. 沒有把畫面、資料庫、內部模組或資料儲存列為外部實體。
4. 每筆資料流都有具體名詞、方向與需求依據。

### 任務 2：建立 1 張系統環境圖

系統環境圖必須包含：

1. 一個代表整個專案範圍的總處理程序：0 校園揪團與共乘／分攤平台。
2. 任務 1 的至少 3 個外部實體。
3. 至少 8 筆外部輸入與輸出資料交換。
4. 清楚方向與可定義的資料流名稱。
5. 與專案章程一致的系統邊界。

**輸出：**

1. 可閱讀的圖片。
2. 可編輯原始檔或圖表語法。
3. 圖下方的範圍與待確認說明。

**完成標準：**

1. 圖中只有一個總處理程序。
2. 圖中沒有資料儲存與內部子程序。
3. 每個外部實體至少有一筆輸入或輸出。
4. 圖中項目都能回到任務 1 與需求來源。

### 任務 3：建立第 0 層資料流程圖

將總處理程序分解為主要業務處理。

最低要求：

1. 4 至 7 個處理程序：1.0 查詢揪團、2.0 建立揪團、3.0 驗證加入條件、4.0 建立與更新成員、5.0 計算分攤結果。
2. 至少 2 個資料儲存：D1 揪團資料、D2 成員與分攤紀錄。
3. 保留系統環境圖中的外部實體。
4. 保留系統環境圖中的外部輸入與輸出。
5. 每個處理程序使用動詞加名詞命名。
6. 每條資料流使用可定義的名詞命名。
7. 資料儲存以保存內容命名，不以技術名稱命名。
8. 不出現外部實體到外部實體、外部實體到資料儲存、資料儲存到資料儲存的直接連線。

**輸出：**

1. 可閱讀的第 0 層資料流程圖圖片。
2. 可編輯原始檔或圖表語法。
3. 處理程序規格摘要。

**完成標準：**另一位同學可以從圖與摘要說明每個主要處理程序的輸入、輸出、讀取、更新與需求依據。

### 任務 4：建立平衡表

逐筆比對系統環境圖與第 0 層資料流程圖。

每筆包含：

1. 外部實體。
2. 系統環境圖資料流。
3. 輸入或輸出方向。
4. 第 0 層對應處理程序與資料流。
5. 平衡、失衡或待說明。
6. 修正方式或資料字典依據。

**輸出：**平衡表。

**完成標準：**系統環境圖的每一筆外部資料流都有第 0 層對應；第 0 層沒有無來源的新增外部資料流。

### 任務 5：執行資料流程錯誤檢查

逐一檢查：

1. 黑洞。
2. 奇蹟。
3. 灰洞。
4. 不允許的直接連線。
5. 沒有名稱或名稱模糊的資料流。
6. 只有輸出或只有輸入且無法說明的資料儲存。
7. 實際是控制順序而不是資料的箭頭。
8. 與需求或流程名稱不一致的項目。

最低要求：找出至少 3 個模型問題或待確認問題。若確認沒有錯誤，也必須提出至少 3 項曾檢查的高風險位置與證據。

**輸出：**問題與修正紀錄。

**完成標準：**每個問題都有症狀、原因、涉及項目、需求依據、修正方式與重查結果。

### 任務 6：建立至少 10 筆資料字典

至少包含：

1. 系統環境圖中的主要輸入：發起揪團表單資料、看板查詢條件、加入請求。
2. 系統環境圖中的主要輸出：新揪團建立結果、揪團卡片資訊、分攤計算結果、滿額狀態。
3. 影響核心處理的內部資料流：可加入結果、成員更新結果。
4. 至少 2 個狀態或規則相關資料項目：滿額狀態、分攤基準。
5. 至少 1 個實作品中容易混淆的欄位：fullStatus、status。

每筆包含：

1. 資料編號。
2. 標準資料名稱。
3. 類型。
4. 定義與組成。
5. 格式、型態或允許值。
6. 來源與去向。
7. 驗證規則。
8. 需求、模型與驗收條件對應。
9. 敏感性或權限注意事項。
10. 待確認問題。

**輸出：**至少 10 筆資料字典。

**完成標準：**另一位同學可以依定義判斷某個畫面欄位或假資料是否符合模型，不需自行猜測資料內容。

### 任務 7：使用程式碼代理檢查實作品欄位

使用程式碼代理（Code Agent）執行唯讀檢查，先不要修改實作品。

檢查範圍：

1. 表單輸入欄位。
2. 列表與詳情顯示欄位。
3. 篩選與排序欄位。
4. 假資料欄位。
5. 狀態名稱與允許值。
6. 驗證規則。
7. 新增、更新與刪除操作使用的資料。

最低要求：

1. 對照至少 10 筆資料字典。
2. 找出「實作多出」「實作缺漏」「名稱不同」「規則不同」或「一致」。
3. 每項結論附檔案位置或畫面位置。
4. 每項建議標示需求依據。
5. 資訊不足時列為待確認，不得自行增加欄位。

**輸出：**

1. 實作品欄位稽核表。
2. 程式碼代理提示詞。
3. 程式碼代理輸出摘要。
4. 採用、不採用與人工修正判斷。

**完成標準：**至少完成一次完整對照，所有修改建議都能回到需求、模型或資料字典。

### 任務 8：建立修正與後續待辦

依問題來源分類：

1. 需求待確認。
2. 系統環境圖修正。
3. 第 0 層資料流程圖修正。
4. 資料字典修正。
5. 實作品修正。
6. 驗收測試修正。

每筆待辦包含：

1. 待辦編號。
2. 問題來源。
3. 受影響項目。
4. 修正內容。
5. 需求依據。
6. 完成標準。
7. 驗證方式。
8. 負責人與狀態。

**輸出：**修正待辦清單。

**完成標準：**不把所有問題都直接交給程式碼代理；需求與業務規則問題保留人工確認。
