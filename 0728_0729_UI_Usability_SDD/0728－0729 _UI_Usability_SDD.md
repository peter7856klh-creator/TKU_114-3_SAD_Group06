### L. 第五切片或介面重構任務書

任務名稱：校園揪團加入流程與狀態同步介面重構 (Fifth Working Slice)
選擇：第五個可運作切片 (Option A)

需求與模型版本：FR-03, FR-04, BR-02 / SRS v1 / Group & JoinRecord v1
原型版本：Prototype v1.2
目前實作版本：Commit a3f892c (切片 4)

目前症狀：當揪團滿額時，UI-02 詳情頁未即時更新為「額滿」狀態，導致使用者仍可點擊加入並產生錯誤。
可重現步驟：進入一筆剩餘名額為 1 的揪團，點擊加入後，畫面未觸發 status 轉移至 'full'，續點產生 duplicate/error。
模型與畫面依據：StateDiagram (open -> full 轉移規則)、UI-02 (ST-03 停用狀態)。

必須保留：既有之表單填寫、GroupJoinController 驗證邏輯與 JoinRecord 寫入。
必須新增或修正：
  1. 於 GroupJoinController 加入 updateStatus 廣播，加入成功後立即同步畫面狀態。
  2. 新增 UI-02 額滿（ST-03）與重複加入（ST-04）之視覺狀態。
本次不做：自動候補輪換機制與金流線上支付。
不可自行決定：取消報名後是否徹底物理刪除 JoinRecord（一律依 BR-02 僅軟刪除/標記 cancelled）。

正常狀態：UI-02 人數未滿，顯示綠色「可報名」按鈕。
替代狀態：UI-02 人數已滿，顯示灰色「已額滿」按鈕，並提示轉候補。
錯誤狀態：UI-05 跳出「不可重複加入」Alert。
停用或權限狀態：團主檢視自身揪團時不顯示「申請加入」，改顯示「管理揪團」。

主要測試：TC-S-01 (報名未滿), TC-S-02 (報名至滿額)。
替代測試：TC-E-01 (重複加入擋下)。
錯誤測試：ERR-01 (滿額時強制送出 API 需回傳正確錯誤訊息)。
狀態測試：open -> full 轉移與畫面 UI 同步測試。
回歸測試：確認原本的發起揪團 (TF-03) 流程不受影響。

完成後回報：
1. 修改檔案與理由。
2. 需求、模型與畫面對照。
3. 實際執行的測試與結果。
4. 未通過項目與剩餘限制。
5. 不得把未執行測試寫成通過。
